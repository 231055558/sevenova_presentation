# Issue模板与申请验收

2026-10-14确认。父Issue由李昊洋与AI讨论确认后发布，小前端不负责发布父Issue。子Issue承载父任务中一个工作方向，可以包含多步操作、多次修改和实验，不要求每一步单独建单，也不强制每个子Issue有独立交付物。

父负责人综合检查各子Issue的结果，对照父任务要求判断整体是否已完成；达到申请验收条件后，再在父Issue下汇总成果。单个子Issue结束不直接触发父任务申请验收，全部子Issue关闭也不自动代表父任务通过。最终验收和Done由李昊洋确认。

## 父Issue模板

```markdown
## 任务目的
要解决什么问题，为什么现在做。

## 工作要求
- 本次需要完成的内容：
- 本次任务基于的基础要求：
- 本次任务允许的视为完成的结论类型：

## 交付物
需要提交哪些代码、配置、数据、报告或演示。
产物可以分散存放，验收时在本Issue评论中汇总链接。

## 验收要求
- [ ] 要求一：
- [ ] 要求二：
- [ ] 要求三：

验收方法：使用什么场景、案例或步骤检查。
验收人：李昊洋；需要协助验证的人员另列。

## 时间与任务评级
计划完成时间：
任务难度评级：
任务工作量评级：

## 接取与分工
负责人：接取后确定一人。
协作人员及分工：由接取人补充。
推进步骤：接取人自行创建子Issue，所有操作需完整记录在子Issue评论中，缺失将会扣除对应分数。

## 任务基础分
由老板确定，未确定时留空。

## 任务最终绩效
```

## 子Issue模板

```markdown

本子Issue承接父任务中的哪部分工作。

## 工作要求
- 需要完成的内容：
- 基于的代码、模型、方案或其他基础：
- 允许视为完成的结论类型：

## 时间与分工
计划完成时间：
负责人：
协作人员及分工：

## 推进记录
实际操作、修改、实验结果、问题和结论持续记录在本Issue评论中。
```

## 父Issue申请验收评论

父负责人评估整体已满足父任务要求后使用：

```text
申请验收

完成情况：
对照任务要求，说明已完成和未完成的部分。

验收结果：
逐项列出测试结果及对应证据。

交付物：
代码／PR：
数据／报告：
运行方法／演示：

已知问题或备注补充：
仍存在的限制和需要继续处理的内容。

参与情况：
各人实际负责的工作及对应子Issue。
```
