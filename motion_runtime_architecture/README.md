# robot_motion_control 目标运行时架构

本目录是 `robot_motion_control` 下一阶段重构的目标架构门户，与同级
`docs/system_flow/` 的职责不同：

- `docs/system_flow/` 描述当前仓库已有 package、合同和缺口。
- 本目录描述计划建设的运行时架构、Module、Interface、Adapter、启动过程、任务过程、
  执行责任、数字孪生和测试体系。

入口：[`index.html`](index.html)

## 文档范围

门户包含：

1. 整体分层和依赖方向。
2. 启动注册、Workflow 编译、RuntimeGraph 构建和任务运行时序。
3. 每个主要 Module 的责任、输入输出、不变量、错误和测试面。
4. 定时轨迹合同、速度信息、主站实时插值和执行监督责任。
5. 真机、数字孪生、Fake、Replay Runtime Pack 的统一注册方式。
6. 无 ROS 单测、数字孪生、ROS 集成、主站模拟和实机验收的测试梯度。
7. 推荐技术栈、目标 package 布局和纵向迁移顺序。

## 状态说明

这是目标架构 `v0`，不是当前实现清单。页面中的 `目标`、`候选`、`当前复用` 标签用于区分：

- 已确认的架构责任；
- 尚需通过原型验证的技术选择；
- 可以先通过 Adapter 复用的当前 package。

具体 IK、抽离、负重等算法细节不在本门户冻结。算法只通过所属能力家族的 Interface、
输入不变量和错误模式进入架构。

## 维护约定

- 结构化内容集中在 `assets/data.js`。
- 页面渲染逻辑集中在 `assets/app.js`。
- 视觉样式集中在 `assets/styles.css`。
- 页面主视图采用语义化 HTML 与 CSS 手工控制布局；`diagrams/*.dot` 和同名 SVG 仅保留为早期详细关系图与历史材料，不得依赖自动排线解决信息分层问题。
- 已确认的关键架构决策同步记录在 [`DECISIONS.md`](DECISIONS.md)。
- 若目标架构发生责任变化，应同时更新相关页面和决策记录，避免图和文字漂移。

## 架构图表达规则

核心图参考 C4 的分层思想，并遵守以下约束：

1. 一张图只回答一个问题，不混合系统边界、内部责任、部署、技术依赖和执行时序。
2. `L1 系统上下文` 只显示目标系统、人员或外部系统；不出现类、协议和技术栈。
3. `L2 运行时容器` 显示稳定责任、主数据流和主要边界；类继承与注册细节放入模块清单。
4. `D1 动态图` 每行只表达一次有方向的交互，用编号表达顺序；反馈必须沿独立时序行返回。
5. 中文是主标签；英文只作为小号代码标识，帮助读者映射到实现。
6. 连线只表达方向，不承载长文本。关系说明使用编号并放在图侧或图下。
7. 深凡戴克棕每张图只强调一个主角；米色表示内部责任，灰橄榄表示外部系统，红色只表示失败或阻断。
8. 桌面图在中小屏幕必须重排为纵向结构，不能仅靠缩放或横向滚动维持布局。
9. 细节通过同页清单或下钻页面展开，不能为了“完整”把所有关系塞回总览。
