C++ 对象系统 · Python 工具 · 可切换通信 · 分阶段迁移

生产运行核心以 C++ 为主，Python 专注工具、实验和分析。

技术选择服从对象边界和测试需求：C++ 负责确定性运行与算法集成，Python 负责配置工具、实验、数据分析和可视化，ROS2 只是跨进程 Communication 实现。

迁移原则

先建立单程序薄对象骨架和确定性测试纵向链，再让当前成熟实现接入准确家族接口。文件迁移服从每条完整 PR 的验收边界。

技术选型

分层技术栈

目标仓库结构

一个程序的内部目录

不创建新的 core/runtime/task/description/MoveIt ROS 包群。统一源码树按对象责任组织，ROS2 只保留部署集成壳。

依赖方向

同一程序也必须保持依赖纪律

放在同一仓库不等于任意互相 include：核心不知道 ROS、MoveIt 或真机，具体对象实现依赖稳定合同和外部库。

配置归属

配置描述对象与流程，不代替代码

系统配置描述 ObjectGraph，任务配置描述 TaskGraph，对象配置描述实现参数；安全事实由 RobotDefinition 与执行合同管理。

迁移路径

从设计基线到唯一运行权威

先建立薄骨架，随后纵向替换适配器；新旧链并行比较时，新链只规划不执行，避免双执行权威。

非目标

第一轮明确不做什么

限制范围是防止架构工程重新变成巨型重写的必要部分。

下一次实现工作应从第一阶段的无 ROS 测试纵向链开始，而不是先移动现有规划算法文件。
