无 ROS → 数字孪生 → ROS 集成 → 软件在环 → 硬件在环

每一级测试都模拟它能负责的世界，并明确不能证明什么。

先用确定性测试替身验证流程，再用数字孪生验证时间与状态，最后用主站软件在环和硬件在环验证真实执行合同；不能把 RViz 动起来等同于真机可靠。

测试核心

稳定接口就是测试面。测试替身和真实适配器接收相同命令、返回相同结果类型，才能系统覆盖失败与恢复路径。

L4 · 验证阶梯

现实程度逐级增加，结论边界始终明确

每一级只增加一类新的现实因素，并说明它能证明什么；高等级验证不替代低等级的快速门禁。

日常主力：L0—L2 · 实机门禁：L5
分级说明

六级验证梯度

越靠下越真实、越昂贵；L0/L1 必须足够快，成为日常修改的基础门禁。

测试替身

为完整任务链需要模拟的部分

不仅模拟机械臂，还要模拟任务源、场景、时间、算法结果、工具、主站错误和观察者故障。

故障注入

必须主动制造的失败

仅测试成功路径无法证明架构能定位问题。每类失败都应产生稳定错误码、关联 ID 和事件链。

纵向切片

建议的纵向验收切片

每个切片从入口穿到结果，避免“所有 IK 都改完但还没有一条任务能跑”的横向大重构。

实机测试限制： HIL/真机测试必须经过人工安全确认，从单段、小幅、低速、空载开始；本门户和自动测试不授权任何真实硬件动作。

数字孪生负责提高覆盖率和诊断效率，但不能代替方向、零位、跟随误差和安全链的真机验收。
